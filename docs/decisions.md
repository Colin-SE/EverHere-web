# 当前实现与范围决策

更新：2026-11-27。本页记录当前代码与报告的关系；旧日期的实施说明保留在 Git 历史和各阶段文档中，不作为现在功能未实现的结论。

1. Web 首版按用户提供的设计报告 F1–F5 对照，O1–O5 后置。11 月 8 日只做 F1–F4 是一次阶段授权；工程 P1–P4 编号不等于报告功能编号。当前差异见 [完成度](feature-completion.md)。
2. 单个 Flask 应用包含相册、回忆录、商城/订单；原生 HTML/CSS/Jinja/JavaScript，MySQL 和 SQLAlchemy/PyMySQL，不增加前端构建要求。
3. Member、SpaceOwnership 保留稳定账号和相册归属；访客须明确认领，登录不自动合并或上传游客资料。普通注册不能获得管理员角色。
4. 时间轴/日历/地点/人物引用同一 LifeRecord；事件时间和审计时间分离，粗精度不编造日期，逾期计划不自动完成。草稿和正式事实分开，版本和回执保护编辑/提交。
5. 投稿冻结所选材料和来源版本；管理员只能处理领取的授权修订，不浏览无关相册，不改原记录。审核和开始生成现为两个操作。
6. 成品、样张及 ready 一致提交；失败保留批准材料可重试。样张只含部分页面，完整文件按订单归属、付款与退款状态授权。
7. 商城独立于回忆录。订单价格、定制文字、照片和修订固定；处理、支付、履约分别记录。处理完成不等于付款或发货。
8. 支付宝模式为 disabled/sandbox/production；没有报告的独立模拟适配器。正式站关闭支付。用户确认沙箱此前已验证可用；本次新建沙箱及其待配置参数另记，不否定历史结论。
9. 当前还没有首次完整下载记账和逐项取消的共同锁定策略，不能宣称已满足报告 F5。真实渠道拒绝与管理员拒绝申请也应区分。
10. 相册同步现使用同一 Flask/MySQL 的 `/v1/sync/*`、`/v1/assets/*`，含回执、冲突和原图校验。不能继续用旧 Fastify/PG 尚缺权益的记录宣称当前同步全部关闭。真机验收需单独证据。
11. 新 `/connections` 只探索已存人物与记录关联；WebGL 地球仍是模型加地点列表，未完成真实事件点位探索。旧 cloud/archive/lifegraph API、旧保险箱和主题切换保持删除。
12. 原图保持原字节，Pillow 校验并制作显示副本。所有读写/图片/PDF/订单接口核对归属和角色，浏览器 CSRF 使用现有服务端机制。报告提出的 Flask-WTF/WTForms 未采用。
13. 数据库变化只追加迁移，当前终点 `20261125_album_sync`；测试只用隔离 SQLite 或 `_test` MySQL，不对真实库运行清表套件，不提交凭据和私人资料。
14. 生产 MySQL、沙箱 SQLite、合成测试、用户确认的历史验收和真机/渠道实测分别记录。源码存在、服务运行、完整流程验收和课程材料提交不是同一个状态。
