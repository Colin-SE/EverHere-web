# F1—F4 阶段实现与使用说明

日期：2026-11-02。范围对应当前设计报告的 F1—F4。功能已迁入 `D:\code\everhere web` 主项目，日常开发与运行均使用 D 盘；原报告源文件未覆盖。

## 本阶段的用户任务

| 功能 | 当前实现 | 入口 |
|---|---|---|
| F1 人生相册 | 保留记录/人物草稿、文字与照片、五种日期精度、同 ID 编辑、时间轴/日历/人物/地点、软删除恢复；新增账户与空间归属映射 | `/` |
| F2 回忆录整理与提交 | 挑选最多 20 条本人记录、章节标题及排序、逐张选择照片、手动保存草稿、明确授权后提交不可变版本；退回后修改并提交新版本 | `/workspace#memoirs` |
| F3 审核与制作 | 管理员领取任务后查看授权材料、填写意见、退回或通过；设置章节顺序与字号，生成固定版式中文/英文 PDF；失败保留材料并重试；作者查看预览 | `/workspace#admin` |
| F4 独立商城 | 管理员维护商品/款式/价格及上下架；用户独立定制奖牌/礼品，或选择本人已完成回忆录的电子/纸质版；创建并查看待支付订单 | `/workspace#shop`、`/workspace#orders` |

人生相册、回忆录、文创商城是并行入口。普通商品不需要任何回忆录。新页面沿用网站的中英文语言偏好，翻译静态界面与校验提示，不翻译用户记录、主题、商品名称、定制文字或审核意见。

F5 支付、取消、退款、地址收集、生产/物流履约和付费高清下载尚未实现。本阶段没有模拟或真实扣款接口，没有发货操作；订单明确保持“待支付”。F3 仅开放带 PREVIEW 标记的预览 PDF，最终成品文件没有公开下载路径。

## 账户与私人资料

- 新 Web 工作流账户存于 `members`，角色为普通用户或制作与商城管理员。保留已删除的旧账户结构的删除记录，不恢复旧 `users` 表或保险箱实现。
- 公开注册只建立普通用户。浏览器提交 `role=admin` 不会获得管理员权限。管理员由服务器维护者通过命令行建立，密码交互输入，不写入配置。
- 访客可以继续使用人生相册。注册时只有明确勾选“将当前访客档案归入新账户”，才将当前签名会话持有的空间与账户关联；否则新建空空间。登录已有账户不会自动吞并访客资料。
- `SpaceOwnership` 对空间使用唯一主键，防止重复认领。认领后旧访客 Cookie 无法继续读取该空间；登录和退出轮换会话及 CSRF。未认领的原访客空间引用保存在签名会话中，退出账户时可返回；若已被认领则不再恢复访客访问。重新登录可找回账户空间。
- 原记录、照片、草稿、人物和归档 ID 保持不变。原 `LifeRecord.user_id` 外键继续指向 `local_spaces`，不是新账户 ID。
- 共同云账户独立管理；本次没有开启云上传、下载或双端同步。

## 回忆录规则

1. 编辑仅限草稿或已退回状态。送审前要求非空标题、至少一个有标题且含正文或照片的章节，以及明确材料授权。
2. 每份最多 20 条记录、正文总计 10 万字、选中原图总计 64 MiB。用户只共享选中章节的正文、日期精度/范围、状态、地点和勾选照片；不复制未选照片、人物关系或整份原始归档。
3. 记录版本必须与用户选择时一致。来源被修改或删除时拒绝提交，用户通过“更新本章素材版本”重新确认。提交保存来源 ID/版本、文字与照片原字节，之后原记录变化不会改动送审快照。
4. 管理员队列未领取任务时只显示状态/版本元数据。领取后只开放此申请的材料；不开放原记录、原图地址或其他私人档案。不同管理员不能处理同一已分配任务，不能审核自己的申请。
5. 审核退回必须有原因。重新提交建立新修订版，保留原快照和审核意见；旧审核页面的版本不能操作新稿件。
6. 管理员只可更改成品章节顺序与字号。修改文字须退回作者修改；没有直接改写原记录的管理员接口。
7. 已通过的修订版才能生成。生成成功后成品、预览和 ready 状态在同一事务提交；生成失败保留 approved 状态与快照，显示可重试错误，不创建成功成品。
8. 本阶段使用同步生成，面向上述有界课程原型；异步任务、更多字体、复杂模板及大批量生产属于后续扩展。

状态转换：草稿 → 待审核 → 需修改 → 新修订版待审核；待审核 → 审核通过/待制作 → 已完成。管理员领取和所有更新校验当前版本；MySQL 写路径加行锁。

## 商城规则

- 管理员管理 `medal`、`gift`、`memoir_digital`、`memoir_paper` 四种款式。价格用整数人民币分表示，数量为 1—10；商品/款式下架后不能新下单。
- 款式可要求定制文字和照片。照片必须属于本人、明确授权本订单使用，最多 10 MiB；下单保存原字节和摘要，之后相册变化不改变定制材料。
- 回忆录款式只能选择本人当前 ready 的修订版；普通礼品不能绑定私人回忆录，也不要求用户先投稿。
- 订单由服务端计算价格，保存商品名称、款式、数量、单价、定制内容与回忆录版本快照。商品价格/版本变化后要求重新确认；历史订单金额不变。
- 同一账户的请求编号唯一：重试同一内容返回同一订单；相同编号配不同内容返回冲突。订单及所有明细任一项失败均回滚。
- 普通用户只能读取自己的订单。F4 不向管理员开放全部订单或私人定制照片；订单任务分配及必要履约访问在 F5 实施。

2026-11-02 用户进一步要求使用真实 MySQL 后，当前工作区已配置被 Git 忽略的 `.env`，复用原项目的本机 `lifealbumweb` 连接，并完成 `20261102_workflows` 追加迁移。迁移前后原相册、照片、草稿与关系数量一致，真实 MySQL 的 `db check` 无模型差异。日常运行使用 `run.py`，默认地址 `http://127.0.0.1:5000/`；源码与 Python 运行环境现均位于 `D:\code\everhere web`。

## 实现位置

- `app/models_workflow.py`：新增账户、空间归属、回忆录、版本/素材、商品及订单模型。
- `app/security.py`、`app/api/accounts.py`：身份、CSRF、角色及空间权限；原相册接口继续按空间隔离。

- `app/api/memoirs.py`、`app/api/shop.py`：回忆录与商城接口。
- `app/templates/workspace.html`、`app/static/js/workspace.js`：新用户/管理员操作页面；原相册增添并行入口。

新 JSON 接口继续使用现有集中 CSRF 与字段校验机制；账户使用 Flask-Login 和 Werkzeug 哈希。没有把 Flask-WTF、支付服务或第三方生产接口写成已安装能力。

## 验证方法与边界

`tests/test_workflows.py` 使用合成数据，覆盖显式认领与旧 Cookie 撤权、角色/归属隔离、不可变文字和照片、退回重提、旧版本拒绝、生成失败重试、独立商城、价格快照、重复下单、失败回滚、私人回忆录购买和保留旧资料的追加迁移。

浏览器验收使用 `tools/workflows-check-server.py` 和 `tools/workflows-browser-check.cjs`。测试服务器只建立一次性内存库及合成管理员，页面截图写入被忽略的 `test-results/workflows/`。它不是可保存个人资料的日常运行入口。

MySQL 隔离测试工具 `tools/workflows-mysql-check.py` 只尝试建立随机名称的 `_test` 库，测试结束删除本进程新建库。现有项目账号返回 MySQL 1044（无权建立新库），因此完整业务与锁并发测试仍需具备隔离测试库权限的连接。真实项目库的连接、追加迁移、模型一致性及 HTTP 健康检查已单独通过；没有在个人资料库运行会清表的测试套件。不能将 SQLite 全套通过写成 MySQL 全套验收通过。
