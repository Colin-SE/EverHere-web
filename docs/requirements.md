## 首版功能

| 编号 | 需求 |
|---|---|
| F1 | 私人文字/照片、同 ID 编辑、草稿、软删除恢复；时间轴/日历/人物/地点同源；归属及日期精度保护，逾期计划不自动完成。 |
| F2 | 最多 20 条本人记录组织主题和章节；明确选图授权；冻结正文、来源 ID/版本、顺序和照片字节；退回和新修订保留历史。 |
| F3 | 独占领取、受分配人员审核/退回/排版/生成；不改原相册；固定版式成品与独立样张；失败可重试，旧版本决定拒绝。 |
| F4 | 奖牌/礼品独立定制下单，冻结文字和授权照片；本人 ready 回忆录选择电子/纸质规格；商品、价格、可用状态和字段校验。 |
| F5 | 服务端结算及实体地址；带标识的模拟支付/退款/履约；付费完整 PDF 授权下载；未付款直接取消、已付款审批后整单取消；每项在首次完整下载或开工前才符合资格。 |

首版使用模拟付款和履约，无实际扣款、印刷订单或派送。报告要求的模拟适配器与支付宝沙箱是不同实现；不能因已接入支付宝就将 F5 所有业务规则标记完成。

## 共用规则

1. 每个记录、原图、草稿、稿件、订单和下载均在服务器检查归属、角色、分配和状态，包括直接 URL。
2. 管理员只读取获授权的稿件/订单材料，不浏览无关相册、不改写来源。
3. 提交快照、订单价格、素材和交付修订固定，来源或目录变化不能静默改写确认内容。
4. 成品、样张和 ready 一致提交；失败保留批准材料，不产生成功状态或下载资格。
5. 取消在同一事务逐项检查，首次完整下载和开工使用共同锁定策略；任一项不符合即拒绝整单取消。样张不算完整下载。
6. 已付款取消经审批后阻止交付；退款失败继续阻止并可重试，业务拒绝保持原单。真实退款依赖渠道确认。
7. 简体中文/English 只改变显示和格式，不改用户原文、地区、身份或枚举。

## 可选与其他规划

O1 宠物/影音；O2 更多模板/礼品规格；O3 AI 草稿；O4 定位记录的交互地球；O5 真实支付、印刷、物流。先完成 F1–F5，再按实际授权接入。

[Android 产品规划 v3](product-plan-v3.md) 保留为长期来源；11 月 25 日任务单中的相册选图、用户管理、回忆录正文/封面和筛选、真机联调另行跟踪。这些扩展不是本报告 F2/F4 的逐字要求，也不能替代 F5。

2026-11-08 只做 F1–F4 是历史批次授权，不改变本报告 F5 的必做地位。工程 P1–P4 与报告 F1–F5 不是同一组编号。

## 实际架构与差异

Web 使用 HTML/CSS/Jinja/原生 JavaScript、Flask、Flask-SQLAlchemy/PyMySQL/MySQL、Flask-Login/Werkzeug、ReportLab/Pillow/pypdf，无前端构建。报告提出的 Flask-WTF/WTForms 尚未采用，当前为 JSON/字段校验和自定义 CSRF。

当前相册同步由同一 Flask/MySQL 的 `/v1/sync/*`、`/v1/assets/*` 提供，复用账户主空间。旧 Fastify/PostgreSQL BFF、旧 `/api/v1/cloud/*` 和 JSON/ZIP 交换不是现在的同步实现。Android 本地架构不因 Web 文档更新而改变。
