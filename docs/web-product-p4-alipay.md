1. 打开 [支付宝沙箱控制台](https://open.alipay.com/develop/sandbox/app)，在原沙箱应用找到接口加签方式。使用 RSA2 普通公钥模式，上传本机 `upload-this-app-public-key.txt` 的完整内容。
2. 从控制台记录沙箱 AppID、沙箱商家 PID 和支付宝公钥；将前两项写入 `settings.json` 的 `appId`、`sellerId`，支付宝公钥保存为 `alipay-public.pem`。商户私钥不发到聊天。若控制台要求特定沙箱网关，填写 `sandboxGateway`；否则留空使用代码支持的默认网关。
3. 服务器 `origin.txt` 使用 `https://sandbox.wyever.com`，通知 URL 为 `https://sandbox.wyever.com/payments/alipay/notify`。同步上述公开参数至服务器并重启独立服务，以 configured 确认配置加载，再检查签名查询和收银台跳转。
4. 测试站直接打开，不再输入入口口令。网站测试管理员账号在本机 `test-access.json` 的 `adminEmail`、`adminPassword`；普通买家通过网站注册，支付宝付款则使用控制台提供的沙箱买家账号。¥1.00 示例纪念牌只用于沙箱测试。
5. 创建一笔实体商品订单，使用测试地址和沙箱买家余额付款。记录商户订单号、支付宝交易号，核对本站已付款、金额一致。分别保存异步通知已验签入账和主动查询结果，浏览器跳回成功本身不算支付证据。
6. 对尚未开始制作的已付款订单申请退款，管理员领取并批准；核对同一退款请求号、沙箱买家余额回退及本站退款状态，确认重复提交没有重复退款或库存释放。
7. 核对超时未付款订单关闭、库存释放、重启后状态保留；如演示电子回忆录，再核对未付款不可完整下载、付款可下载、退款撤销后续下载。
8. 核对制作、物流录入、收货仅更新相应履约状态。若沙箱提供业务账单，按商户单号和退款请求号对账；未取得渠道账单时该项登记为待验收。

## 交易边界

- 单个订单只生成一个支付宝交易号，设备重试复用相同的商户单号、金额和绝对到期时间。服务端用 RSA2 验签，核对应用、卖家、商户单号、交易号及金额。浏览器返回只触发服务端查单。可信支付状态由异步通知或签名查询更新。
- 签发收银台链接前冻结实体地址并预占有限库存。未跟踪库存的款式按不限量处理。限量库存以可售件数管理，关单和全额退款只释放一次。30 分钟到期，先查单再关单。关单后补到的付款进入人工核对和原路退款流程。
- 本轮的退款按整单全额处理。实体订单开工前可申请，由订单负责人审批。支付请求结果不明时，用原退款请求号核对再重试。已付款的电子回忆录按冻结版本交付，申请退款起撤销后续下载权限。
- 实体交付按开始制作、手工录入物流并发货、买家确认收货流转。P3 的客服处理状态继续独立。当前提供支付宝电脑网站收银台、手工物流记录和业务账单差异核对。部分退款、自动物流查询和独立售后退件流程后续按经营规则扩展。

## 正式部署与验收

正式配置默认 `ALIPAY_MODE=disabled`。先核对目标环境并迁移至当前头 `20261125_album_sync`，使用 `flask db check` 验证结构，按正式商户配置填写 `.env.example` 中对应变量及专用密钥文件。启用前安排正式 HTTPS 回调、受限服务账户和周期任务 `flask --app wsgi expire-alipay-orders`，并验证重启后关单任务继续执行。测试站单独运行每 30 秒一次的关单检查。

支付宝业务账单下载后，解压中文交易明细 CSV。运行 `flask --app wsgi reconcile-alipay --date YYYY-MM-DD --bill {path}`，按北京时间自然日核对确认支付和退款记录。迟到的渠道结果可能形成跨日差异，使用原交易号和退款请求号复核。本命令只报告差异。

本地自动化通过隔离数据库和合成签名网关验收，覆盖签名、重复回调、关单晚到付款、并发付款、库存、退款重试、授权下载、分配后的发货和账单差异。真实收银台、支付宝发出的回调、沙箱退款与真实账单需提供相应沙箱或正式交易证据后逐项记录。
